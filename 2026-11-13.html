함께 볼 점 모델 카드의 성능은 Google이 제시한 평가 조건을 기준으로 합니다. 모델은 사실과 다른 내용을 생성할 수 있고 기능 제공 범위는 서비스별로 다를 수 있습니다.

업무에 연결하면 모델을 시험할 때 실제 질문 몇 가지를 같은 조건으로 비교하고 응답 시간, 근거와 결과의 정확도를 함께 확인해 보세요.

연구용 AI 작업을 추적하고 중단하는 Control Room

함께 볼 점 이는 OpenAI 내부 연구 인프라에 관한 설명입니다. 사용자에게 제공되는 일반적인 ChatGPT 관리 기능이라고 해석해서는 안 되며, 모델 출력 중단과 실행 프로세스 종료도 구별해야 합니다.

AWS, AgentCore 실행 환경의 새 버전 소개

고급

여러 문서에서 답변과 근거를 함께 찾기

같은 질문에 답하기 위해 여러 지침과 회의록을 뒤져야 한다면 에이전트가 먼저 관련 문장을 찾아 답변 초안을 만들도록 해 보겠습니다. 자료 간 내용이 다를 때는 어느 문서가 맞는지 임의로 정하지 않게 하는 것이 핵심입니다.

이렇게 요청해 보세요

목표: 지정한 문서에서 질문에 대한 답과 근거를 찾습니다. 파일을 읽기만 하고 변경하거나 외부로 전송하지 마세요. 먼저 읽을 문서와 버전, 질문에 관련된 항목을 목록으로 보여 주세요. 각 답변은 주장 | 근거 문서·제목·문장 | 문서 날짜 | 확인 상태로 작성하세요. 근거가 없으면 모른다고 답하고, 자료가 충돌하면 양쪽 근거와 확인 질문을 나란히 적어 주세요. 답변과 직접 관계없는 문서는 근거로 쓰지 마세요. [문서 폴더] [질문]

결과를 확인할 때

인용 문장이 실제 답을 뒷받침하는지와 문서의 최신 버전을 직접 확인합니다. 권한과 회사의 자료 취급 기준을 확인한 뒤 사용하고, 문서에 없는 내용은 담당자에게 문의하세요.

용어 정리

근거
답변의 내용을 확인할 수 있는 문서의 위치와 해당 문장입니다.
중급

명세를 바탕으로 assertion 후보와 근거 정리하기

인터페이스 명세에서 검증 속성을 만들 때는 신호 이름보다 먼저 어떤 조건에서 어떤 동작이 보장돼야 하는지 확인해야 합니다. AI에게 후보 속성을 정리하게 하고, 각 속성의 근거와 가정부터 검토해 보겠습니다.

이렇게 요청해 보세요

아래 인터페이스 명세와 신호 정의를 읽고 assertion 후보를 정리해 주세요. 후보마다 확인할 동작 | 발생 조건 | 기대 동작 | 관련 clock·reset | 명세 근거 | 확인할 가정을 표로 작성하세요. 우선 한국어 문장으로 속성을 설명하고, 명세에서 확인할 수 없는 타이밍은 질문으로 남겨 주세요. 이후 각 후보에 대한 SystemVerilog Assertion 초안을 별도로 제시하되, 확인되지 않은 부분은 주석으로 표시하세요. [명세] [신호 정의]

결과를 확인할 때

담당자가 clock edge, reset 비활성화 조건과 신호의 주기 관계를 원문 및 파형에 대조합니다. vacuous pass 가능성과 오류를 놓치는 경우를 살피고, 승인된 시뮬레이터 또는 formal 환경에서 컴파일과 동작을 검증하세요.

용어 정리

Assertion
설계가 만족해야 할 조건을 기술하고 검증 과정에서 확인하는 구문 또는 속성입니다.
기초

측정표에서 단위가 섞인 항목 찾기

측정 결과를 모으면 같은 항목이 서로 다른 단위로 기록될 수 있습니다. 값을 바로 비교하기 전에 원래 단위와 변환 근거를 함께 남겨 보겠습니다.

이렇게 요청해 보세요

아래 측정표에서 같은 항목에 서로 다른 단위가 쓰인 부분을 찾아 주세요. 항목 | 원래 값과 단위 | 통일할 단위 | 변환한 값 | 원문 위치를 표로 작성하세요. 단위가 없거나 측정 조건이 달라 비교가 어려운 항목은 변환해 단정하지 말고 확인 필요로 남겨 주세요. [측정표]

결과를 확인할 때

변환 배율과 소수점 위치를 계산기로 다시 확인합니다. 전압·온도·부하 등 조건이 다른 값은 단위만 맞췄다고 직접 비교할 수 없으므로 원본 시험 조건도 확인하세요.

용어 정리

단위 변환

중급

Timeout 로그에서 확인할 경로 정리하기

초기화나 통신 중 timeout이 발생하면 로그의 마지막 메시지만 보고 원인을 정하기 쉽습니다. 함수 흐름과 로그를 함께 살펴보고, 기다린 대상과 다음에 확인할 경로를 나눠 보겠습니다.

이렇게 요청해 보세요

아래 timeout 로그와 관련 코드 또는 실행 흐름을 비교해 주세요. 1. timeout이 발생한 위치, 기다리는 조건, 시간 제한과 근거를 정리해 주세요. 2. 그 조건을 바꿀 수 있는 호출 경로와 관련 상태를 코드 위치와 함께 나열하세요. 3. 가능한 원인은 가설로 표시하고 각각을 확인할 로그·계측·재현 조건을 제안하세요. 코드나 로그에서 확인할 수 없는 경로와 값은 만들지 마세요. [로그] [관련 코드 또는 호출 흐름]

결과를 확인할 때

timeout이 실제 오류인지 앞선 실패의 결과인지 확인합니다. 시간 단위와 재시도 조건을 코드에서 대조하고, 제안된 가설은 동일한 보드·FW·설정에서 재현해 확인하세요.

용어 정리

Timeout
정해진 시간 안에 기대한 응답이나 조건을 얻지 못해 대기를 끝내는 동작입니다.
기초

계약서에서 담당자에게 확인할 질문 만들기

계약서를 처음 살펴볼 때는 곧바로 판단을 내리기보다 업무에 영향을 주는 조건과 확인이 필요한 문장을 찾는 데 AI를 활용할 수 있습니다.

이렇게 요청해 보세요

아래 계약서에서 계약 기간, 갱신·해지 조건, 대금 지급, 납기와 책임 범위를 찾아 주세요. 각 항목의 해당 조항과 문장을 함께 적고, 내용이 불명확하거나 문서에서 찾지 못한 부분은 확인 질문으로 정리해 주세요. 문서에 없는 조건이나 법적 결론은 만들어내지 마세요. [검토할 계약서]

결과를 확인할 때

조항과 날짜, 금액을 원문에서 확인하고 별도 합의서가 있는지도 살펴봅니다. 법적 해석과 계약 체결 여부는 회사의 담당자 또는 법률 검토를 거쳐 결정하세요. 자료를 입력할 때는 회사의 도구별 취급 기준을 따릅니다.
